Architecture Proposal  ·  Draft 3

Nonchalant

One primitive. A process holds its own state, yields values over time, and does not care which side of the wire it runs on.

SPA-only · No SSR TypeScript, strict — examples type-checked Successor to Sprezzatura + acto August 2026
01

The thesis

A process is an async generator. Its state is plain local variables. It communicates only by receiving messages and yielding values — which means it does not know, and does not need to know, whether it is running in this tab or in a Node worker three thousand kilometres away.

Everything in Nonchalant is a Process: a piece of state is a process of data, a view is a process of UI, a derivation is a process with no mailbox, and a remote actor is a process whose yields arrive over a socket. They share one type, one lifecycle, and one set of rules.

Because a process communicates only through messages and yields, its location is a deployment decision rather than an architectural one. Because its yields are projected into a synchronously-readable value, the renderer never learns where that value came from. Because the wire carries structural patches of plain data rather than markup, the protocol is implementable in any language — and the same patches drive a canvas, a terminal, or a test harness as readily as a DOM.

Nobody holds all three pieces. Solid 2.0: fine-grained reactivity and first-class async, but components run once and location is not a concept. Crank: generator components with real local state, but a virtual DOM and a client-only world. LiveView: server-held state and location transparency, but BEAM-only, HTML over the wire. Nonchalant is the intersection: generator processes with plain-let state, fine-grained output, and a location-transparent, DOM-agnostic wire.

03

The review: what draft 2 got wrong

This draft exists because exercising draft 2 against real applications — forms, typeahead, routing, query caching, undo — broke it in six places. Each break produced a design.

FoundRead granularity was asserted, not designed

Draft 2 said patches apply “into the fine-grained graph” but never said how a binding reading cart().total avoids re-running when items[3].done flips. Without an answer, every yield wakes every binding — coarse-grained rendering wearing fine-grained clothes. Design: write plain, read tracked (§05).

FoundNo request/response

send is fire-and-forget, so a form cannot learn whether its own submission succeeded without grovelling through yielded status fields. Erlang has call and cast; draft 2 only had cast. Design: Call messages and ask() (§04), typed end-to-end and carried by two new wire ops.

Foundconnect(url) → Process conflated transport with address

A host runs many processes; a URL identifies the host, not the actor. And the same gap existed locally: draft 2 had no way to share a process by name — no dependency injection, no keyed caching. One missing concept, felt in three places. Design: the Registry (§06) — lookup(name, args) is get-or-spawn, locally and remotely, and it is also the query cache.

FoundMailbox semantics under await were undefined

A for await body that awaits a fetch is not listening; messages queue behind it. Correct for a checkout, wrong for a typeahead, and draft 2 didn't say which you get. Design: FIFO by default, self.latest() to skip to the newest — backpressure and drop-stale as explicit, visible choices (§07).

FoundCrash behaviour was a word, not a mechanism

“Supervision” appeared four times with no answer to: what do readers see mid-crash, what restarts, what happens to queued messages. Design: restart policies, last-good-value reads with stale, bounded mailbox retention (§08).

FoundKeyed lists are a diff, and the doc pretended otherwise

“No vdom” was overclaimed. When a list thunk re-runs, the sink must reconcile children by key — a localized diff, the same one Solid's For and lit's repeat perform. Every fine-grained framework carries this one diff; honesty is better than a slogan (§05).

Verification. Every signature and example in this draft was compiled together under tsc --strict on TypeScript 7.0.2, including the negative cases: sending a call-message, asking a cast, reading a no-initial process as total, wrong registry arg arity — all rejected at compile time, checked with @ts-expect-error. The reconcile numbers in §08 are measured, not estimated.
04

The type, in full

One noun, its two faces. The outside face is what a holder of a process can do; the inside face — Self — is what the generator itself receives.

// ————— the outside face —————
interface ProcessBase<T> {
  (): T                                      // synchronous read of the latest yield
  readonly pending: boolean                  // working towards its next yield
  readonly stale:   boolean                  // value survives a crash or a partition
  readonly error:   unknown                  // last failure, if any
  [Symbol.asyncIterator](): AsyncIterator<T> // lossy latest-value stream, multicast
  [Symbol.dispose](): void                   // ends the process; finally blocks run
}

// a message that expects an answer
type Call<Req, Res> = Req & { readonly reply: (res: Res) => void }

// send() accepts the casts; ask() accepts the calls — and neither accepts the other
type Process<T, In = never> = ProcessBase<T>
  & ([Plain<In>]    extends [never] ? {} : { send(msg: Plain<In>): void })
  & ([Requests<In>] extends [never] ? {} : {
      ask<M extends Omit<Requests<In>, 'reply'>>(msg: M):
        Promise<Res<Extract<Requests<In>, M & object>>>
    })

// ————— the inside face —————
interface Self<In> extends AsyncIterable<In> {   // FIFO mailbox, backpressured
  readonly signal: AbortSignal    // aborts on dispose — thread it into every fetch
  latest(): AsyncIterable<In>     // skip to the newest message, dropping the queue
  send(msg: In): void             // post to own inbox — the actor self-send
}

type Proc<T, In, Args> = (self: Self<In>, args: Args) => AsyncGenerator<T>

Three constructors and a sink, unchanged in count from draft 2, refined in signature:

// initial value decides whether reads are total — the type tells the truth
function spawn<T, In, A>(proc: Proc<T, In, A>, args: A):                        Process<T | undefined, In>
function spawn<T, In, A>(proc: Proc<T, In, A>, args: A, opts: { initial: T }): Process<T, In>

function derive<T>(fn: () => T): Process<T>        // pure, memoised, no mailbox
function mount<Out>(sink: Sink<Out> | Element, view: Process<Out | undefined>): Disposable

And the message discipline in use — casts and calls in one union, distinguished by shape, enforced by the compiler:

type CartMsg =
  | { type: 'add';    item: Item }                              // cast
  | { type: 'remove'; id: number }                              // cast
  | Call<{ type: 'checkout' }, { ok: boolean; orderId?: string }>  // call

cart.send({ type: 'add', item })             // fine
cart.send({ type: 'checkout' })              // ✗ compile error: checkout is a call
const res = await cart.ask({ type: 'checkout' })   // res: { ok: boolean; orderId?: string }

Inside the generator, a call arrives as an ordinary message carrying reply. Over the wire, ask becomes a correlated call/reply op pair; locally it is a resolver in the message. The generator cannot tell which.

Every dynamic slot in a view normalises. A value, a thunk, a Process, a Promise, an AsyncIterable, a node, or an array of any of those — one internal toProcess(x) lifts them all. A pending promise holds only its own slot; nothing above re-renders, nothing below unmounts, no boundary is declared.
05

Write plain, read tracked

State is written as plain immutable data in generator locals. Granularity is recovered on the read side — where it is safe — not imposed on the write side, where a decade of Vue scar tissue says it hurts.

The pipeline for every yield, local or remote:

generator yields next
  → patch = reconcile(prev, next)      // identity-guarded structural diff → ops on paths
  → snapshot ← next                     // the process's current value, plain and frozen
  → notify(patch)                       // wake only readers whose paths intersect the ops

The missing half from draft 2 is the read side. When cart() is called inside a tracked context — a binding, an effect, a derivation — it returns the snapshot wrapped in an ephemeral get-only proxy that records which paths the reader touched. () => cart().total records /total; a patch op on /items/3/done does not intersect it, and the binding sleeps through the update. Called outside a tracked context, cart() returns the raw snapshot — zero proxy overhead in ordinary application logic.

This dodges the classic deep-proxy scars deliberately: there are no write traps (state is immutable snapshots), no reactive-vs-raw identity split (the proxy lives only for the duration of a tracked read), and no Map/Set instrumentation problem (collections are diffed structurally, not trapped). The proxy answers one question — what did this reader look at? — and vanishes.

State processes and view processes

Same type, distinguished only by yield rate. A state process yields often — once per message. A view process yields rarely, usually once: it yields a tree of bindings whose holes are thunks and processes, so value changes flow through the graph without resuming the generator. Re-yielding is for structural change — a route swap, a mode change. A view process re-yielding at value-change frequency is a performance bug, and the dev build says so.

The one diff we keep, named honestly

When a list thunk re-runs — () => cart().items.map(i => li({ key: i.id }, …)) — the sink reconciles the produced children against the DOM by key: reference-equal nodes are skipped, moved keys move DOM nodes, new keys construct, absent keys dispose. This is a localized keyed diff, the same one Solid's For and lit-html's repeat perform, and every fine-grained framework carries it. “No vdom” means no whole-tree diffing on every update — not a claim that list reconciliation is magic. And because state patches carry splice ops with exact indices, a binding whose recorded path is exactly the list can often skip the re-map entirely and translate the splice straight into DOM inserts and removes — the optimisation is available precisely because the wire format is the change format.

06

Names: the registry

One concept was missing from draft 2, and its absence was being felt as three different problems: dependency injection, query caching, and remote addressing. Erlang solved all three the same way — a registry of named processes.

interface Registry<S extends Schema> {
  lookup<K extends keyof S & string>(name: K, args: ArgsOf<S[K]>): ProcessOf<S[K]>
}

// the same operation at every distance:
const cart  = registry.lookup('cart', { userId })          // this tab
const shop  = connect<Shop>('wss://api.example')          // a transport to another registry
const rcart = shop.lookup('cart', { userId })              // same call, other side of the wire

lookup is get-or-spawn: the first caller under a name starts the process; every later caller shares it. That one behaviour is, simultaneously:

  • Dependency injection. A deep view needs the session? lookup('session'). No prop-drilling, no context API — the registry is the context, and unlike a context it works identically outside the view tree.
  • Query caching. lookup(['user', id], …) with a composite key is TanStack Query's queryKey re-derived from first principles: dedup by key, shared by all readers, refcounted by watchers, evicted after an idle timeout. Section 07 builds it in twenty lines.
  • Remote addressing. connect(url) returns a Registry, not a Process — fixing draft 2's conflation. A host publishes a typed schema of what may be looked up; the schema is simultaneously the TypeScript contract and the security whitelist. Nothing outside it can be spawned remotely.

Location transparency, restated more strongly than before: the unit of sharing is a name, and a name resolves the same way at every distance — this tab, a worker, a server.

The wire, second revision

// client → host
{ op: 'lookup', ref, name, args }         // get-or-spawn by schema name
{ op: 'send',   ref, msg }
{ op: 'call',   ref, id, msg }            // ask() — correlated request
{ op: 'exit',   ref }

// host → client
{ op: 'yield',  ref, patch }              // reconcile(prev, next), same codec as local
{ op: 'reply',  ref, id, value }
{ op: 'done',   ref, value? }
{ op: 'raise',  ref, error }

type Patch = Op[]
type Op = ['set', path: string, value: Json]
       | ['del', path: string]
       | ['splice', path: string, start: number, remove: number, insert: Json[]]

Eight ops, transport-agnostic, no framework or DOM concepts. Any language can host it. And because the client and a Node host share a language, one capability falls out that LiveView structurally cannot have: optimistic prediction by running the same generator on both sides. lookup with a predict option spawns a local twin of the server process, applies sends to it immediately for zero-latency UI, and reconciles against authoritative patches when they arrive — same code, no hand-written optimistic reducer, divergence corrected by the same patch mechanism as everything else.

07

Exercises: the design under load

Five problems that other libraries exist to solve, worked in full. Each compiled under strict TypeScript. The measure of the design is how little of it each one needs.

Typeahead — cancellation and racing

The problem that acto's flatMapLatest existed for, and the graveyard of hand-rolled debounce. The mailbox's two iteration modes carry it:

type Query = { q: string }
type SearchState = { q: string; results: Result[]; pending: boolean }

async function* Search(self: Self<Query>, { api }: { api: Api }): AsyncGenerator<SearchState> {
  let results: Result[] = []
  yield { q: '', results, pending: false }

  for await (const { q } of self.latest()) {     // stale keystrokes never even arrive
    yield { q, results, pending: true }
    try {
      results = await api.search(q, { signal: self.signal })
      yield { q, results, pending: false }
    } catch { /* aborted or failed; the loop simply continues */ }
  }
}

latest() gives exactly flatMapLatest's observable behaviour: while the fetch is in flight the loop is not listening, and on completion it resumes at the newest pending query, skipping everything between. For hard mid-flight cancellation, the classic actor move is available: spawn the fetch as a task that posts its result back via self.send, and abort the previous controller on each new query. Both patterns are ordinary code — no operator library required.

A form — request/response closing the loop

type SignupMsg =
  | { type: 'set'; field: 'email' | 'name'; value: string }
  | Call<{ type: 'submit' }, { ok: true } | { ok: false; errors: string[] }>

async function* Signup(self: Self<SignupMsg>, { api }: { api: Api }) {
  let form = { email: '', name: '', errors: [] as string[], submitting: false }
  yield form
  for await (const msg of self) {
    switch (msg.type) {
      case 'set':
        form = { ...form, [msg.field]: msg.value, errors: validate(form) }
        break
      case 'submit': {
        yield form = { ...form, submitting: true }
        const res = await api.signup(form, { signal: self.signal })
        msg.reply(res.ok ? { ok: true } : { ok: false, errors: res.errors })
        form = { ...form, submitting: false, errors: res.ok ? [] : res.errors }
      }
    }
    yield form
  }
}

// the view closes the loop without watching status fields:
button({ onclick: async () => {
  const r = await form.ask({ type: 'submit' })
  if (r.ok) router.send({ type: 'nav', to: '/welcome' })
}}, 'Create account')

FIFO backpressure is doing quiet work here: a second submit clicked mid-flight queues behind the first instead of racing it. The bug every hand-rolled form has, absent by construction.

A router — code splitting inside the language

A router is a state process whose values are view processes. Lazy loading needs no framework feature at all — the body is async, so import() is just an expression:

async function* Router(self: Self<never>, { location }: { location: Process<Route> }) {
  let current: Process<VNode | undefined> | null = null
  for await (const route of location) {           // a Process is an AsyncIterable
    current?.[Symbol.dispose]()                     // previous page's whole scope ends
    switch (route.name) {
      case 'home':
        yield current = spawn(HomeView, { route }); break
      case 'admin': {
        yield Spinner()                             // interim yield: loading state
        const { AdminView } = await import('./admin.js')   // code splitting = await
        yield current = spawn(AdminView, { route })
      }
    }
  }
}

Everything a router needs is visible in fourteen lines: the URL is a process, navigation is iteration, a loading state is an interim yield, code splitting is await import, and teardown of the outgoing page is one explicit dispose — which cascades through the page's entire scope, closing the leak class that killed acto.

A query cache — TanStack's core in twenty lines

function userQuery(id: string): Process<User | undefined> {
  return registry.lookup(['user', id], {
    proc: async function* (self: Self<{ type: 'refresh' }>) {
      let user = await fetchUser(id, { signal: self.signal })
      yield user
      for await (const _ of self) {                    // 'refresh' → revalidate
        yield user = await fetchUser(id, { signal: self.signal })
      }
    },
    evict: 30_000,      // unwatched for 30s → disposed; next lookup refetches
  })
}

Dedup is lookup's get-or-spawn. Sharing is the registry. Refcounting is the watcher graph — the unwatched hook the TC39 proposal legitimises. Stale-while-revalidate is the process keeping its last yield while it fetches the next, which is what pending already means. None of this is a data-fetching framework; it is the same five concepts arranged in a different order. What it deliberately does not attempt: normalised cross-query caches and query invalidation graphs — at that point, use a sync engine; the pitch is not “a better TanStack.”

Undo/redo — processes compose as functions

Because a process is a function, middleware is function composition — no store enhancers, no plugin API:

type Hist = { type: 'undo' } | { type: 'redo' }

function withHistory<T, In, A>(proc: Proc<T, In, A>, depth = 100): Proc<T, In | Hist, A> {
  return async function* (self, args) {
    const inner = channel<In>(self.signal)         // a private Self for the wrapped proc
    const it = proc(inner, args)
    let current = (await it.next()).value as T
    const past: T[] = [], future: T[] = []
    yield current
    for await (const msg of self) {
      if (msg.type === 'undo' && past.length)   { future.push(current); current = past.pop()! }
      else if (msg.type === 'redo' && future.length) { past.push(current); current = future.pop()! }
      else {
        past.push(current); if (past.length > depth) past.shift()
        future.length = 0
        inner.send(msg as In)
        current = (await it.next()).value as T    // convention: one yield per message
      }
      yield current
    }
  }
}

const cart = spawn(withHistory(CartProc), { userId })
cart.send({ type: 'undo' })       // typed: In | Hist, checked

The same shape gives logging, persistence, time-travel debugging, and message replay. The one caveat is stated in the code: this wrapper assumes the reduce-style one-yield-per-message convention; a general version forwards yield streams. Redux middleware, Vuex plugins, and Zustand middlewares are all this pattern with a framework in the way.

Two more, briefly

Multi-tab sync

A BroadcastChannel transport is ~40 lines against the same 8-op protocol: one tab elects leader and hosts; the rest connect to it. No new concepts — the wire never assumed a server, only a transport.

Exit animations

A sink concern, correctly outside the core: the DOM sink's dispose path supports a deferral hook (run the transition, then detach). The process model is untouched — disposal order was already deterministic.

08

Engineering the risks

Draft 2 listed risks. This draft designs against them, with numbers where numbers could be had.

reconcile, measured

A prototype structural diff (identity-guard before recursion, paths built only on the changed spine — the guard alone was worth 5×), on the 10k-item shape from the exercises, Node v22.12:

RegimeCost per yieldVerdict
Immutable update, 1 of 10,000 items changed46 µsFree at interaction rate; fine at 60 fps
Immutable append to 10,00038 µsSame
Immutable update, 1 of 100,000759 µsFine per keystroke; not per frame — that scan is the O(n) floor
Zero structural sharing, 10,000 items (mutate-and-clone style)~4,900 µsThe pathology. Dev build detects and names it
Small state (a form, a HUD, Mario), even with zero sharing3.8 µsNever matters

The design guidance this buys: yields at interaction rate are unconditionally fine; yields at frame rate want frame-sized state — which is what per-frame state looks like anyway (Mario is five numbers, and diffs in well under a microsecond). The dev build watches the ratio of visited nodes to emitted ops; a large walk that emits almost nothing means the yields share no structure, and the warning says exactly that: “this process yields deep clones — mutate less, spread more.”

Crashes: the supervision design

spawn(proc, args, {
  initial,
  restart: (error: unknown, n: number) => n < 3 ? backoff(n) : 'stop',  // or 'never' | 'always'
})
  • Readers never see a hole. A crashed process keeps returning its last yield, with stale: true and error set. A binding can render the error, dim the stale value, or ignore it — but it always has a value to render.
  • Restart re-runs the generator from its original args — the Erlang position: init state is the recovery state. Casts arriving while down are retained in a bounded mailbox and replayed; pending asks reject — a caller awaiting a reply deserves the truth, not a silent retry.
  • Ownership is structural. Anything spawned inside a process body attaches to that process's scope and dies with it, recursively — the router's single dispose call tears down a whole page. Sharing across scopes goes through the registry, whose entries are owned by watchers, not by spawners.
  • The remaining gap is named, not hidden: no preemption. A process in a hot synchronous loop stalls its host thread; the BEAM would schedule around it, JavaScript cannot. Worker-thread hosts partition the blast radius. The language-agnostic protocol remains the honest hedge.

The thunk tax, priced

() => cart().total in every dynamic slot is the visible cost of having no compiler, and it stays. What draft 3 adds is the accounting: a Process is already callable, so passing one directly needs no wrapper; static values need nothing; and the four-token arrow buys REPL-and-script-tag usability, zero build configuration, and views that are ordinary expressions in ordinary TypeScript. Svelte pays a compiler for those four tokens. It is a defensible trade stated as a trade — and if it ever proves wrong, a purely optional Vite plugin that compiles thunks away is additive, not architectural.

Partitions

A disconnected remote process keeps serving its last value with stale: true; casts queue bounded locally; asks race a timeout and reject; reconnection re-lookups by name, and the host replays a fresh full patch (op paths from root), which the same apply path treats as just a large patch. With predict enabled, queued casts have already been applied to the local twin, and the post-reconnect authoritative patch reconciles the divergence — rebase as a special case of the ordinary mechanism.

12

Settled, and still open

Newly settled by the review: read-side path tracking (write plain, read tracked); Call/ask request-response; the registry with typed schemas, unifying DI, caching and remote addressing; connect returning a Registry; mailbox semantics — FIFO with latest(), answering draft 2's open question; initial deciding T | undefined vs T in the type, answering the other; supervision, partition and prediction designs; reconcile relocated to core with measured budgets.

Is per-yield epoch scoping worth adding?

The router disposes its outgoing page explicitly — one line, visible, correct. The alternative is automatic: children spawned between two yields die when the next yield's tree mounts. Less to forget; more magic to explain; and state processes spawning long-lived children would need an escape (self.spawn).

Recommend  Ship explicit-first. Epoch scoping is additive sugar; adopt it only if real apps show the manual dispose being forgotten in practice.

How much of the predict/rebase design is v1?

Prediction is the wire's showpiece, but correct rebase against authoritative patches has real edge cases (predicted splices vs authoritative splices on the same array). The mechanism is the ordinary patch path, but the reconciliation policy needs design time.

Recommend  v1 ships stale + queued casts + replay on reconnect. predict lands behind an option flag once property tests cover splice-vs-splice rebase.

Bounded mailboxes: what is the overflow policy?

Erlang mailboxes are unbounded and that is a famous failure mode. A bounded default needs an overflow rule: drop-oldest, drop-newest, or crash the sender's expectation (send stays fire-and-forget, so backpressure cannot reach a caller synchronously).

Recommend  Default bound with drop-oldest for casts plus a dev warning; ask is naturally bounded by its pending promise. Make the bound a spawn option.

Does the name survive contact with npm?
